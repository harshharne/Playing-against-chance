ON Turning it on

About five minutes. Four Terminal windows on the Mac, called A, B, C and D here. Go in order; each step says what to wait for.

  1. Mac · AStart the GPU machine
    gcloud compute instances start chance-rtx --zone=asia-south1-c
    "done". Then wait one minute: it can't take connections yet ("Connection refused").
  2. Mac · ASend the latest code
    First pull in GitHub Desktop. If it complains about trajectory.json, discard that file's changes.
    it ends with "Sent." and says whether the server needs a restart.
  3. VM · BStart the server
    gcloud compute ssh chance-rtx --zone=asia-south1-c
    You're now inside the machine (Ubuntu's welcome text). Then:
    cd ~/stream-proto && source .venv/bin/activate && PAINTER=sdxl python stream_server.py
    "[animate] ready", about a minute. Leave this window open: it's the log.
  4. Mac · COpen the tunnel
    gcloud compute ssh chance-rtx --zone=asia-south1-c -- -N -L 8766:localhost:8766
    it prints nothing and looks stuck; that's right. Leave it open. Server above turns green.
  5. Mac · DStart the die reader
    In its window, the first time or if the tray moved: c click 6–10 points on the tray's inside edge, Enter · l lock · take the die out, e empty tray. Throw once to check.
    Die reader above turns green.
  6. ChromeOpen the piece
    Open the control panel, then the game (the cards at the top). In both: ⌘⇧R. On the game: F fullscreen, then click once so it may play sound.
    the game is black. Throw the die: the life begins.

OFF Turning it off

Two minutes. The last step is the one that matters: a running GPU machine spends credit every hour, even doing nothing.

  1. ChromeClose the game and the panel
    Or leave the game black: it waits for a throw.
  2. Mac · DStop the die reader
    Press q in its camera window.
  3. VM · BStop the server
    Press CtrlC in its window, then:
    exit
  4. Mac · CClose the tunnel
    Press CtrlC in its window.
  5. Mac · AStop the GPU machine
    Always. A running machine costs about US$0.74 an hour; a stopped one only cents a month.
    gcloud compute instances stop chance-rtx --zone=asia-south1-c
    To be sure it's off:
    gcloud compute instances list
    chance-rtx shows STATUS TERMINATED.

When something's wrong

"Connection refused" after starting the machine
It's still waking up. Wait a minute and run the same command again.
The tunnel says "Address already in use"
An old tunnel is still open. Close it, then run step 4 again:
lsof -ti:8766 | xargs kill
The page looks like an old version
Reload without the cache: ⌘⇧R.
"command not found: python"
On the Mac it's python3. On the VM, python works once source .venv/bin/activate has run.
No voice
Click once on the game page (Chrome blocks sound until then). Hover the Voice pill on the panel: it says why. No openai.key: add it (first time, below) and run push.sh again.
The die isn't read, or misread
Start the die reader before opening the game (or reload the game after). In its window: d shows what it sees. Sliders: sensitivity up if glare counts as the die, dot_dark up if dots are missed, area_inset down to skip the tray's rim. Without a die: R in the game, or ROLL on the panel.
"No space left on device" (on the VM)
Clears caches only, nothing the game needs:
pip cache purge; sudo apt-get clean; sudo journalctl --vacuum-size=200M; df -h /
The machine won't start (no capacity)
Google has no free GPU in that zone right now. Try again in a few minutes.

First time on a Mac

Install the die reader's tools
python3 -m pip install opencv-python numpy
If it refuses ("externally-managed-environment"), add --user.
The keys (Claude for the director, OpenAI for the voice)
One file each, inside stream-proto. Paste your key between the quotes; never into a chat. Git ignores .key files; push.sh carries them to the machine.
Allow the camera for Terminal
System Settings → Privacy & Security → Camera → Terminal on. Then start the die reader again.
